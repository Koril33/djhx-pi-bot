# 记忆管理后台：产品设计

## 目标与范围

给唯一管理员提供比 Telegram 命令更直观的管理入口。当前版本覆盖运行概览、会话、用量费用、长期记忆、会话摘要、记忆预算和邮件配置，不承载网页聊天或服务器终端。

入口为 `https://pi.djhx.site/admin`。桌面和手机均可使用；页面采用深色底、细边框与少量青绿色强调。页面文案只保留操作所需的名称、状态和结果。

## 页面

| 页面 | 操作 |
|---|---|
| 登录 | 使用 `.env` 中唯一的管理员用户名和密码登录。 |
| 概览 | 查看 Bot 与 pi 进程状态、是否忙碌、当前会话和模型、Telegram 更新队列及最近失败更新的故障类型；核对后可标记已处理。 |
| 会话管理 | 按用户列出、新建、切换、重命名会话；标出 JSONL 状态及 SQLite 摘要是否存在。 |
| 用量费用 | 查看今天、近 7 天、近 30 天的 token、缓存命中和估算费用；聊天与记忆维护分列，并标识未计价、价格待复核和未完成回合。 |
| 长期记忆 | 按 Telegram 用户切换，搜索、添加、编辑、置顶和删除记忆；显示来源与当前数量。 |
| 会话摘要 | 按用户查看各会话摘要，清空指定摘要。 |
| 人格管理 | 创建、编辑、启停和删除结构化人格；查看生成的追加提示词，为用户切换当前人格并运行独立测试。 |
| 记忆设置 | 开关自动提取；调整摘要间隔、重试时间、近期回合保留、入库截断、摘要输入与回复预算、记忆数量与长度、注入数量与字节预算。 |
| 邮件设置 | 保存 SMTP 服务器、端口、用户名、授权码、发件邮箱；向指定地址发送测试邮件。 |

删除记忆或清空摘要在页面内需要第二次点击确认。删除只影响 SQLite 后续注入，不会抹除旧 JSONL、已经发送的消息或模型服务端留存内容。清空摘要也不会删除该会话的原始回合；已有 `covered_turn_id` 保留，因此不是“重新摘要全部历史”的操作。

## 规则

- 管理员身份由 `.env` 的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 定义，首版不建立管理员账户表。两项均留空时后台登录关闭。
- 记忆按 Telegram 用户隔离，页面选择用户后，写操作仍校验所属用户；不能以记忆 ID 修改其他人的记录。
- 长期记忆总数和单条长度使用当前预算。新增或编辑的内容沿用既有的敏感凭据检查。
- 设置保存到同一个 SQLite 数据库并即时作用于后续处理；重启后仍生效。首次保存后，后台中的记忆参数优先于对应 `MEMORY_*` 环境变量。模型、密钥和服务开关继续由环境配置管理。
- 邮件配置是单实例全局配置。授权码写入 SQLite 的 `smtp_settings`，页面仅显示是否已保存，留空可保留旧值。数据库和一致性备份都包含授权码，迁移与备份时按密钥保护。
- 465 使用连接建立时的 SSL/TLS；587 在认证前先执行 STARTTLS。两种模式都验证服务器证书，不降级为明文认证。聊天 Pi 仅在用户明确要求发邮件并提供收件地址时调用 `send_email` 工具；该工具的参数和结果不包含 SMTP 凭据。Pi 仍以服务账号运行，并保有既有的文件与命令工具，因此服务账号本身可以读取 SQLite。邮件以纯文本发送，不支持附件或批量收件人。
- “发送成功”表示 SMTP 服务器接受邮件，不代表收件箱已投递。测试邮件需要管理员主动提交收件地址。邮件正文可能包含模型生成内容，发送前应在聊天中明确目的地址。
- 注入预算中，“恢复摘要预算 + 记忆条目预算”不得超过总注入预算。页面和服务端共同校验范围。
- 修改记忆会尝试刷新当前空闲会话的注入上下文；忙碌会话由下一轮消息刷新。参数改变不回写历史记录或旧成本。
- 会话新建与切换复用 Telegram 命令的 Pi/SQLite 流程，忙碌时拒绝，失败时尝试恢复原会话。缺失 JSONL 时按现有 SQLite 摘要和近期文字回合恢复；原始工具输出与图片无法恢复。重命名修改本项目 SQLite 中的显示名称，不改写归档 JSONL 内的 Pi 名称。
- 失败的 Telegram 更新可能已经产生工具副作用，后台只展示 ID、时间和故障类型，不展示原始消息，也不自动重放。标记已处理后保留原记录用于去重与短期审计，但不再计入当前失败数和健康告警；失败与已处理记录都在 30 天后清理。
- 用量来自项目 SQLite 账本，金额按价格配置估算，不代表 DeepSeek 官方实扣。缓存命中率按缓存读取 token ÷（缓存读取 + 未命中输入 token）计算；最近记录不受上方时间范围筛选。

## 暂不包含

管理员找回密码、多管理员与角色、批量导入导出、FTS5、逐条历史编辑、审批自动记忆。迁移与备份仍使用单个 SQLite 文件；管理员密码须在新服务器单独配置。
