# 记忆管理后台：产品设计

## 目标与范围

给唯一管理员提供比 Telegram 命令更直观的管理入口。当前版本覆盖运行概览、会话、用量费用、长期记忆、会话摘要、记忆预算和邮件配置，不承载网页聊天或服务器终端。

入口为 `https://pi.djhx.site/admin`。桌面和手机均可使用；页面采用深色底、细边框与少量青绿色强调。页面文案只保留操作所需的名称、状态和结果。

## 页面

| 页面 | 操作 |
|---|---|
| 登录 | 使用 `.env` 中唯一的管理员用户名和密码登录。 |
| 概览 | 查看 Bot 与 pi 状态、当前会话与实际/持久化模型、队列、最近成功完整备份时间与会话数；旧失败更新核对后可标记已处理。 |
| 会话管理 | 按用户列出、新建、切换、重命名会话；标出 JSONL 状态及 SQLite 摘要是否存在。 |
| 用量费用 | 按会话、日期、模型筛选 token、缓存命中和费用；聊天、记忆维护、人格测试分列，未计价调用单列并分页。 |
| 长期记忆 | 按用户搜索、分页、添加、编辑、置顶和删除；显示满额状态，可查看近重复/可能冲突候选，核对内容后确认合并并保留置顶。 |
| 会话摘要 | 按用户查看各会话摘要，清空指定摘要。 |
| 人格管理 | 创建、编辑、启停和删除结构化人格；查看生成的追加提示词，为用户切换当前人格并运行独立测试。 |
| 记忆设置 | 调整自动提取、摘要间隔与预算、近期回合保留、记忆容量与注入预算；确认后可恢复 `.env` 默认值。 |
| 邮件设置 | 保存 SMTP 服务器、端口、用户名、授权码、发件邮箱；向指定地址发送测试邮件。 |

删除记忆或清空摘要在页面内需要第二次点击确认。删除只影响 SQLite 后续注入，不会抹除旧 JSONL、已经发送的消息或模型服务端留存内容。清空摘要也不会删除该会话的原始回合；已有 `covered_turn_id` 保留，因此不是“重新摘要全部历史”的操作。

## 规则

- 管理员身份由 `.env` 的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 定义，首版不建立管理员账户表。两项均留空时后台登录关闭。
- 记忆按 Telegram 用户隔离，页面选择用户后，写操作仍校验所属用户；不能以记忆 ID 修改其他人的记录。
- 长期记忆总数和单条长度使用当前预算。新增或编辑的内容沿用既有的敏感凭据检查。
- 满额不自动逐出记忆，精确重复只刷新日期。整理候选由本地启发式提出，可能存在误判；页面展示原条目和可编辑的保留内容，管理员明确确认后才原子合并。确认版本、归属与敏感内容校验均在服务端执行，任一条被改动或置顶变化后旧预览失效。
- 设置保存到同一个 SQLite 数据库并即时作用于后续处理；重启后仍生效。后台记忆参数优先于对应 `MEMORY_*` 环境变量；恢复默认值清除这些覆盖。模型启动默认值、密钥和服务开关由环境配置管理；用户选择及会话模型/人格组合另保存在 SQLite。
- 邮件配置是单实例全局配置。授权码写入项目 `.env` 的 `SMTP_PASSWORD`，SQLite `smtp_settings.password` 只存 `env:SMTP_PASSWORD` 引用；页面仅显示是否已保存，留空保留旧值。启动将旧数据库明文迁入 `.env` 后清理数据库页，不配置邮件时不创建 `.env`。读取密码直接读取当前文件，不依赖旧进程环境缓存；引用存在但文件缺失时显示未配置。迁移到新服务器需另行配置 SMTP 密码，旧版本数据库和备份仍按密钥保护。
- 465 使用连接建立时的 SSL/TLS；587 在认证前先执行 STARTTLS。两种模式都验证服务器证书，不降级为明文认证。聊天 Pi 仅在用户明确要求发邮件并提供收件地址时创建持久化草稿；完整预览并确认后才连接 SMTP。草稿跨重启保留，24 小时后不能发送；历史状态在 Telegram `/mail history`、`/mail status <ID>` 查询，不自动重发。工具参数和结果不含 SMTP 凭据；服务账号及其 Pi 文件/命令工具拥有相同文件权限，这不构成操作系统隔离。邮件仅支持单收件人纯文本，不支持附件。
- “发送成功”表示 SMTP 服务器接受邮件，不代表收件箱已投递。测试邮件需要管理员主动提交收件地址。邮件正文可能包含模型生成内容，发送前应在聊天中明确目的地址。
- 注入预算中，“恢复摘要预算 + 记忆条目预算”不得超过总注入预算。页面和服务端共同校验范围。
- 修改记忆会尝试刷新当前空闲会话的注入上下文；忙碌会话由下一轮消息刷新。参数改变不回写历史记录或旧成本。
- 会话新建与切换复用 Telegram 命令的 Pi/SQLite 流程，忙碌时拒绝，失败时尝试恢复原会话。缺失 JSONL 时先展示部分或空白恢复范围，确认后从 SQLite 摘要与近期文字恢复；原始工具输出与图片无法只靠 SQLite 恢复。重命名修改 SQLite 显示名，不改写归档 JSONL 内的 Pi 名称。
- 失败的 Telegram 更新可能已经产生工具副作用，后台只展示安全元数据与风险，不展示原始消息，也不自动重放。标记已处理后保留去重记录但不再计入待核对事故数；失败与已处理记录都在 30 天后清理。`/healthz` 就绪状态与旧事故分开，历史失败本身不再持续使服务降级。
- 用量来自项目 SQLite 账本，金额按价格配置估算，不代表 DeepSeek 官方实扣。缓存命中率按缓存读取 token ÷（缓存读取 + 未命中输入 token）计算；最近记录不受上方时间范围筛选。

## 暂不包含

管理员找回密码、多管理员与角色、网页批量导入导出、FTS5、逐条历史编辑及逐条审批自动记忆。完整迁移使用 SQLite 加 JSONL 备份工具，见 [开发运维文档](admin-development.md)；管理员密码、Bot 与模型凭据须在新服务器另行配置。内置备份保存在本机，异机副本仍需安排。
