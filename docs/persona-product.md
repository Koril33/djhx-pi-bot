# 人格管理系统

## 用途

管理员在 `/admin/personas` 创建和管理多个聊天人格。每个人格由名称以及六个文本区域组成：身份、性格、沟通风格、行为规则、背景、偏好。身份必填；每区最多 4000 字符，正文合计最多 12000 字符。后台可预览、保存、启停、删除，并用独立的 Pi 会话测试一条消息。

默认人格来自纳入 Git 的 `prompts/default-persona.json`，首次初始化时写入 SQLite，之后不再自动覆盖。旧 `prompts/persona.md` 仅作历史参考。迁移到新服务器时，复制 SQLite 即可保留人格、选择状态、长期记忆与摘要；仓库仍需包含生成器和默认模板。

## 选择与生效

`personas` 保存全局可选人格，`user_persona_selection` 保存每位 Telegram 用户的当前选择。没有选择时使用 `default`。管理员可在列表中为选中的用户切换；对话中可用 `/persona current`、`/persona list`、`/persona use <id>`。选择对该用户的全部会话有效，不会改写旧消息或 JSONL。停用或删除当前人格时，用户回退到默认人格；默认人格可编辑，不能停用或删除。

聊天 Pi 使用 SQLite 内容生成个人追加提示词文件，通过 `--append-system-prompt` 加载。每条新消息前会比较生成内容；变化时停止空闲的 Pi RPC 进程，再用同一个 JSONL 会话文件启动。进行中的回合不会被后台编辑打断；新设定从下一条消息开始生效。历史对话仍会作为上下文影响回答，若需要完全隔离的风格比较，应新建会话。

## 预览与测试

编辑页显示保存版本的完整人格追加提示词。点击“预览提示词”可查看未保存草稿生成的确切文本；它不改数据库。Pi 自身的基础系统提示、工具说明、动态记忆和会话历史不是人格表生成的内容，因此不包含在这个预览中。

“运行测试”使用保存版本，创建临时的无会话、无工具、无扩展 Pi 实例；不写入聊天 JSONL，不发送邮件，不注入记忆。测试会调用该用户已启动会话中的当前模型；尚未启动时使用配置的默认模型，消耗 token。用量和估算费用以 `persona_test` 来源记录，后台用量页单列；输出展示在测试页面。测试结果只验证人格本身的表现，实际聊天还会受到用户消息、历史会话与记忆的影响。

## 边界

人格只规定角色与表达方式，个人经历与偏好可以放入长期记忆，单个项目细节保留在会话摘要。人格内容会进入模型上下文并增加 token 成本，应保持简短；不要存入密码或令牌。人格文本是可编辑的模型指令，只允许单管理员修改。页面按原后台的签名会话、CSRF 与 HTML 转义规则处理。
